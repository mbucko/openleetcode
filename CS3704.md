## What differs from the upstream README

| Upstream README                     | CS3704                                              |
|-------------------------------------|-----------------------------------------------------|
| clone `mbucko/openleetcode`         | clone `CS3704-VT/Openleetcode`                      |
| Windows: `.\install`                | Windows: `.\install.bat`                            |
| edit the installed `problems/` tree | edit the source `data/problems/` tree               |
| `solution.cpp` / `solution.py`      | also `solution_expected.*` and `solution.md`        |
| Python CLI                          | also needs `jsonschema` (`uv sync` / `pip install`) |

## Quick start

```sh
git clone https://github.com/CS3704-VT/Openleetcode
cd Openleetcode
./install.sh --prefix=./install      # Windows: .\install.bat --prefix=./install
cd install/OpenLeetCode
./openleetcode.sh --language cpp --problem TwoSum --testcase All --verbose
```

More details on how to get started are available in the agent-generated [orientation file](./.opencode/skills/learning-opportunities/resources/orientation.md)

## Source vs. installed layout

The README's `problems/` tree is the *installed* copy (`install/OpenLeetCode/`).
You edit files under **`data/`** in the repository; the build copies:

| Source (edit these) | Installed (generated by the build) |
|---------------------|------------------------------------|
| `data/problems/`    | `install/OpenLeetCode/problems/`   |
| `data/languages/`   | `install/OpenLeetCode/languages/`  |

## Adding a problem

Add problems under `data/problems/<ProblemName>/`, mirroring `data/problems/TwoSum/` exactly:

```text
data/problems/<ProblemName>/
├── description.md
├── cpp/
│   ├── solution.cpp
│   ├── solution_expected.cpp
│   └── solution.md
├── python/
│   ├── solution.py
│   ├── solution_expected.py
│   └── solution.md
└── testcases/
    ├── TestCase1.test
    └── ...            # at least five, including boundary/edge cases
```

Only the target language's directory is required for a given contribution.

## Test case format

Each `.test` file lists one argument per line, with the expected result on the
final line:

```text
<arg1>
<arg2>
<expected result>
```

Supported types: integral, string, boolean, array, or a TreeNode (array
representation). Run the shipped reference with `--run-expected-tests` to
sanity-check your cases.

## Build and verify

```sh
./install.sh --prefix=./install
cd install/OpenLeetCode
./openleetcode.sh --language <cpp|python> --problem <ProblemName> --testcase All --verbose
```

## Contribution workflow

Open an issue proposing a problem → claim an issue created by a **different**
student → implement it on a branch (e.g. `problem/<name>`) → open a pull request
that references the issue → peer-review another student's PR → reconcile
requested changes.

## Requirements

- Python, CMake 3.12, Git
- `jsonschema` for the Python CLI (`uv sync` or `pip install jsonschema`)
- npm (UI only)
